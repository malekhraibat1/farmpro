# فارما برو — نظام إدارة ومحاسبة الصيدلية

تطبيق ويب (React + TypeScript + Vite) لإدارة الصيدلية: نقطة بيع، مخزون وأدوية، دفتر حسابات الصيدليات والشركات، مصاريف، وتقارير. يعمل على الكمبيوتر والهاتف ويمكن تثبيته كتطبيق (PWA) والعمل دون إنترنت.

تصميم وبرمجة: المهندس مالك حريبات

## التشغيل

```bash
npm install
npm run dev        # http://localhost:3000
npm test           # اختبارات الوحدة (111 اختباراً)
npm run lint       # فحص TypeScript
npm run build      # بناء النسخة النهائية في dist/
```

يتطلب Node.js 20 أو أحدث.

## النشر على Vercel

1. ارفع المشروع إلى GitHub.
2. في Vercel: Add New → Project → اختر المستودع (الإعدادات الافتراضية لـ Vite تعمل).
3. لا تحتاج متغيرات بيئة.

عند نشر نسخة جديدة غيّر رقم `VERSION` في `public/sw.js` ليتحدّث التخزين المؤقت عند المستخدمين.

## المزايا الرئيسية

- **نقطة البيع:** بحث عربي ذكي (يتجاهل التشكيل والهمزات)، باركود، بيع بالعبوة أو بالشريط/الحبة، تعليق واستئناف الفواتير، اختصارات (F4 بحث، F8 تعليق، F9 دفع)، بدائل بنفس المادة الفعالة عند نفاد الصنف، بيانات الوصفة للأدوية الخاضعة للرقابة، حد خصم للصيدلي، منع البيع بخسارة، طباعة إيصال وملصقات صرف.
- **المخزون:** تشغيلات (Batches) لكل دواء بتاريخ انتهاء وتكلفة، صرف الأقدم انتهاءً أولاً (FEFO)، سجل حركة المخزون، جرد بالباركود، مرتجعات الشركات والإتلاف، قائمة النواقص واقتراح الطلب من المبيعات الفعلية.
- **المشتريات:** فواتير شراء من الشركات مع البونص والخصم، وتسجيل المستحق للشركة تلقائياً.
- **المحاسبة:** ربح دقيق من تكلفة كل تشغيلة وقت البيع، إغلاق الورديات (النقد المتوقع مقابل المعدود)، سجل الوصفات والرقابة، سجل تدقيق.

## كيف تُحفظ البيانات

- **محلياً:** في IndexedDB داخل متصفح الجهاز (مساحة كبيرة، تعمل دون إنترنت). تُنقل تلقائياً البيانات القديمة من localStorage. لا يوجد تشفير للبيانات المحلية (التشفير بمفتاح داخل الكود لا يحمي شيئاً). الحماية: قفل الجهاز + PIN + النسخ الاحتياطي المشفّر.
- **نسخ احتياطي:** من الإعدادات → تصدير نسخة مشفّرة بكلمة مرور (AES-GCM + PBKDF2). احتفظ بنسخة أسبوعية على الأقل.
- **سحابياً (اختياري):** مزامنة مع Supabase. كل صيدلية = حساب Supabase خاص بها (بريد وكلمة مرور)، ومحمية بـ Row Level Security.

## إعداد Supabase (آمن)

1. أنشئ مشروعاً على supabase.com.
2. من SQL Editor شغّل سكربت **المخطط الآمن (الإصدار 2)** كاملاً (تجده داخل نافذة الربط السحابي، أو في `SUPABASE_SQL_SCHEMA` في `src/services/supabaseService.ts`).
3. في البرنامج: الربط السحابي → أدخل رابط المشروع ومفتاح `anon` (وليس `service_role`) → أنشئ حساباً → سجّل الدخول → ارفع البيانات.

**لا تعطّل RLS ولا تمنح الدور anon صلاحيات.** ذلك يكشف بيانات الصيدلية لأي شخص على الإنترنت.

إن كانت لديك جداول من النسخة القديمة فشغّل `SUPABASE_MIGRATION_SQL` أولاً (بعد أخذ نسخة احتياطية واستبدال `YOUR-USER-UUID`).

## ما تغيّر في هذه النسخة

انظر `CHANGES.md`. اختبارات المتصفح في مجلد `e2e/`.

## قيود معروفة

- الصلاحيات (مدير/صيدلي/سوبر أدمن) والترخيص تُدار داخل المتصفح، فهي تمنع الاستخدام العادي غير المقصود لكنها لا تمنع مستخدماً تقنياً يملك الجهاز. الترخيص الحقيقي يحتاج خادماً.
- المشتريات وحركات المخزون والورديات وسجل التدقيق محلية وتدخل في النسخة الاحتياطية، لكنها لا تُزامَن مع Supabase بعد (الأدوية والفواتير والحسابات تُزامَن).
- عدم وجود تنبيهات تداخل دوائي: لا تبنِها من عندك؛ استخدم قاعدة بيانات مرخّصة إن احتجتها.
- التأمين الصحي وتبادل الأدوية بين الصيدليات كمستندات رسمية غير مُنفَّذين بعد.
- المزامنة السحابية رفع/سحب كامل (آخر كتابة تفوز) وليست مزامنة لحظية متعددة الأجهزة.
- الاستيراد يدعم `.xlsx` و`.csv` فقط (ملفات `.xls` القديمة تُحفظ من Excel بصيغة xlsx أولاً).
